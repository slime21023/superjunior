## When to use it

Apply during multi-step work, delegation, blocked reviews, changed priorities, or any handoff with unclear responsibility.

## Apply it

Identify who carries the outcome to completion and who can resolve consequential decisions. One agent or person can hold several roles on a small task.

Keep active work small enough to finish and verify. Remove blockers before starting unrelated work. State a blocker as a missing fact or decision, its effect, and the person or capability that can resolve it.

Delegate only when permitted and useful. Supply current instructions, bounded scope, required evidence, and return conditions. Avoid overlapping writes to shared artifacts. Inspect worker returns before integration; the owner remains responsible for the result.

## Example and record

An explorer returns caller contracts; an implementer returns a scoped change. The owner reconciles both, checks the integrated candidate, and decides the next phase.

A handoff records current scope and artifact, completed checks, unresolved gaps, latest user corrections, and the next action.

## Boundary

Ownership does not require multiple agents, a new queue, or a separate status document. A new owner receives the existing scope and permissions.
