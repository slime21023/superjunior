## Purpose

Turn user intent into observable behavior that someone else can implement and verify.

## When to use

The expected behavior, constraints, or acceptance conditions need clarification.

## What to provide

The requested outcome, project constraints, and any existing requirements or decisions.

## What you get

A specification in the project’s root `_spec/` with observable acceptance criteria and material open decisions.

## Use with

Give the confirmed criteria to [design-component](/skills/design-component/) when several components must cooperate. See [workflow combinations](/workflows/) for the handoff.
